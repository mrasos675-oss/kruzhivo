# КружИИво

КружИИво помогает проводить антикоррупционную экспертизу проектов нормативных правовых актов: выделяет возможные риски, показывает цитаты и возражения, сохраняет решения специалиста и формирует отчёт. Цепочка проверки: **Аналитик → Проверяющий → Редактор → решение человека**. Исходный документ автоматически не изменяется; выводы ИИ предварительные.

## Требования и зависимости

Нужны Git, Node.js и npm. Обе версии проверены локально на **Node.js 24.13.1 и npm 11.8.0**. В `package.json` указан Node.js `>=22.19.0`; другие версии Node.js/npm, Windows и Linux в этой проверке не запускались.

Зависимости перечислены в `package.json`, точные версии и транзитивные зависимости закреплены в `package-lock.json`. Устанавливайте их командой **`npm ci`**, которая использует lock-файл. Для первой установки нужен доступ к реестру npm (либо заполненный локальный кеш). Отдельная установка Python, базы данных и облачных сервисов для локальной демонстрации не нужна.

Прямые зависимости обеих версий: `@fontsource/jetbrains-mono`, `@neondatabase/serverless`, `@sparticuz/chromium`, `@vercel/blob`, `@vercel/functions`, `ipaddr.js`, `pagedjs`, `puppeteer-core`, `undici`. Часть используется облачным адаптером и экспортом; локальные данные сохраняются в JSON.

## Клонирование и запуск

**Конкурсный коммит** — отдельная папка и фиксированная версия:

```sh
git clone https://github.com/mrasos675-oss/kruzhivo.git kruzhivo-contest
cd kruzhivo-contest
git checkout --detach 1aec734cfa61f2fd0e84351a5cb6e70e5dc9a9ca
npm ci
npm start
```

**Актуальная версия main** — отдельная папка:

```sh
git clone --branch main https://github.com/mrasos675-oss/kruzhivo.git kruzhivo-main
cd kruzhivo-main
npm ci
npm start
```

Если GitHub запрашивает доступ, используйте учётную запись с доступом к репозиторию. Состав доступных файлов зависит от прав просмотра.

Откройте **http://127.0.0.1:4310**. Сервер слушает только локальный адрес. Для остановки нажмите **Ctrl+C** в терминале сервера. Запускайте версии по очереди: обе используют порт 4310. Для другого порта задайте `PORT=4311` в локальном файле `.env` и измените адрес в браузере.

Сборка перед локальным запуском не требуется. `npm run dev` запускает сервер с перезапуском при изменении кода. `npm test` выполняет проверки с подставными ответами провайдеров, без платных вызовов.

При первом запуске создаются три учебных документа. Документы и решения хранятся в `data/workspace.json`, загруженные оригиналы — в `data/originals/`. Перезапуск сохраняет данные; папки двух версий независимы. Локальный вход не требует регистрации и пароля. Облачная версия имеет отдельные правила входа и хранения.

## Демонстрация без ключа и расходов

Сценарий одинаков для конкурсного коммита и main. Учебные документы скрыты из обычного списка «Мои проверки», поэтому используйте прямую ссылку на подготовленный результат.

1. Оставьте `npm start` работающим. Во втором терминале выполните команду ниже; она только читает локальные учебные данные и печатает адрес:

   ```sh
   node -e 'fetch("http://127.0.0.1:4310/api/bootstrap").then(r=>r.json()).then(b=>console.log("http://127.0.0.1:4310/gov/checks/"+b.documents.find(d=>d.name==="Порядок выдачи разрешения").runs[0].id))'
   ```

2. Откройте напечатанный адрес в браузере. Появится «Порядок выдачи разрешения» с тремя замечаниями и отметкой «Учебный режим».
3. Откройте замечание к пункту 2.5. Изучите цитату и материалы трёх агентов: Проверяющий обращает внимание на уточнение срока в пункте 2.6.
4. Нажмите «Отклонить», укажите причину и сохраните решение. Перейдите в «Отчёт» и скачайте Word: решение и объяснение должны остаться в отчёте. Пока другие замечания не рассмотрены, отчёт предварительный.
5. Перезапустите сервер и повторно откройте напечатанный адрес: сохранённое решение останется. «Повторить проверку» создаёт отдельный запуск; для учебного текста оставьте вариант «Подготовленные ответы без обращения к модели».

Учебные ответы подготовлены заранее для эталонного текста. Это демонстрация процесса, а не реальная проверка произвольного НПА. Для собственного текста нужен API-режим.

## Polza — необязательный реальный анализ

Для учебного сценария этот раздел не нужен. Настройки одинаковы в обеих версиях и соответствуют `server/providers.mjs`:

- Провайдер: **«Польза AI (Polza.ai)»**, внутренний ID `polza`.
- Базовый адрес: `https://polza.ai/api/v1`; формат: `chat-completions`. Профиль заполняет их автоматически.
- ID модели: точный ID доступной текстовой модели из вашего кабинета Polza; приложение не проверяет доступность модели при сохранении.
- Ключ: только ваш собственный. Условный пример — `YOUR_POLZA_API_KEY`; это не действующий ключ.

Локально откройте «Работа ИИ агентов» → «Добавить API-ключ» (или «Настроить API-подключение»), выберите провайдера, введите ID модели и ключ, сохраните настройки. Ключ из этой формы остаётся в памяти локального сервера до остановки и не возвращается через API.

Альтернатива — создать локальный `.env` рядом с `package.json` и перезапустить сервер:

```dotenv
LLM_PROVIDER=polza
LLM_MODEL=MODEL_ID_FROM_POLZA
LLM_API_KEY=YOUR_POLZA_API_KEY
LLM_JSON_MODE=true
PORT=4310
```

Замените условные значения своими. Файл `.env` хранит ключ на диске; он исключён из Git, не прикладывайте его к материалам конкурса.

Затем создайте «Новую проверку», загрузите DOCX или вставьте текст, проверьте извлечённый текст и отправьте документ на анализ. Сохранение настроек не вызывает модель. **Запуск анализа и диагностика подключения обращаются к провайдеру и могут расходовать средства.** Текст документа, включённые проверенные источники и допустимые примеры передаются провайдеру. В рамках проверки этого README реальные запросы к Polza не выполнялись.

## Ограничения и проверка инструкции

Это прототип поддержки экспертизы. Человек проверяет источники, применимость норм, замечания и правки. Каталог из 12 факторов — рабочая версия. Подтверждение внутри системы не является квалифицированной электронной подписью. Локальная демонстрация не требует настройки Vercel, облачного хранилища или общего API-ключа.

Проверка 22.11.2026: установка из lock-файла в чистых папках через локальный кеш npm, запуск сервера и автоматические проверки — **172 теста конкурсного коммита и 174 теста актуального кода main**. Проверены учебный анализ, решения, Word-отчёт и сохранность данных. Файлы конкурсной копии сверены по Git-хешам; в копии main сверены все файлы, кроме шести новых WebP-иллюстраций, которые подключение GitHub не позволило скачать. Эти изображения не требуются для серверного сценария.

Обычное клонирование в проверочной среде не прошло из-за отсутствия GitHub-авторизации: копии восстановлены через подключение GitHub и сверены с деревьями коммитов. Браузерное прохождение, внешний доступ жюри, другие ОС и реальный ответ Polza не проверены.
