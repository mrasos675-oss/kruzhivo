# КружИИво — демонстрация системы

Локальное веб-приложение по макетам Penpot: широкие строки документов, обзор результатов, две равные колонки экспертизы, шрифт Inter Tight и общий набор компонентов. Работает на Mac, Windows и Linux с **Node.js 22.19+ или 24 LTS**. Зависимости закреплены в package-lock.json.

Актуальная компоновка и сценарии описаны в [сверке реализации](docs/layout-alignment.md). Файл preview.jpg относится к первоначальной версии интерфейса.

## Запуск

В папке репозитория выполните:

```sh
npm ci
npm start
```

Откройте **http://127.0.0.1:4310**. Для остановки сервера нажмите Ctrl+C в терминале.

При первом запуске появляются три учебных документа. Данные автоматически сохраняются на этом компьютере в `data/workspace.json`, оригиналы новых DOCX — в `data/originals/`. Перезапуск приложения их не удаляет. Код и локальные данные разделены; `data/` и `.env` исключены из Git.

## Что показать на демо

1. Откройте «Порядок выдачи разрешения»: три подготовленные находки.
2. Откройте список результатов, затем пункт 2.5. В блоке «Материалы проверки» Проверяющий показывает уточнение срока в пункте 2.6.
3. Нажмите «Отклонить», укажите причину и сохраните. После подтверждения или отклонения приложение переходит к следующему замечанию; после последнего — к отчёту.
4. В отчёте находка остаётся в группе отклонённых с объяснением специалиста. Скачайте настоящий DOCX.
5. Создайте новую версию или повторный запуск. В истории останутся предыдущие результаты и решения.
6. Создайте документ через «Загрузить учебный пример», чтобы пройти сценарий с начала.

Учебный режим работает без ключа, сетевых вызовов и расходов. Ответы заранее подготовлены **только для учебных документов**. Для произвольного документа учебный режим выдаёт понятную ошибку, а не имитирует анализ.

## Реальный анализ через выбранный API

Откройте «Настройки API», выберите провайдера, укажите произвольный ID текстовой модели и свой ключ. Для собственного совместимого сервиса задайте публичный HTTPS-адрес и формат API. Готовые профили: OpenAI, DeepSeek, OpenRouter, Anthropic/Claude, Google Gemini, Groq, Mistral. Поддерживаются Chat Completions, Responses, Messages и generateContent; подробности и ограничения — в [описании подключений](docs/api-providers.md). После загрузки DOCX или вставки текста выберите API-режим. Роли выполняются отдельными последовательными вызовами:

- **Аналитик:** находит возможные риски по 12 факторам, возвращает точную цитату, объяснение и ссылки на предоставленные нормы.
- **Проверяющий:** оспаривает каждую находку с учётом других пунктов, исключений, применимости и актуальности источников.
- **Редактор:** для выдержавших перепроверку находок готовит проект правки и оценивает изменение смысла. Исходник не изменяется. Материалы трёх ролей доступны под полями решения, а не заменяют решение специалиста.

Окончательное решение сохраняет специалист. Редактор не заменяет это решение. Если находок нет, последующие этапы пропускаются; если нет подходящих после перепроверки, редактор пропускается.

**Сеть и расходы:** в API-режиме полный текст документа, снимок включённых проверенных источников и при анализе проверенные примеры передаются выбранному провайдеру. Запросы оплачиваются по вашему ключу. Сохранение настроек не вызывает модель. Интеграция проверена на подставных ответах четырёх протоколов, реальные платные запросы при разработке не выполнялись.

Ключ из настроек API хранится только в памяти локального сервера до его остановки, не в localStorage и не в JSON с документами. Его нельзя прочитать обратно через API. Альтернатива для собственного компьютера: скопировать `.env.example` в `.env` и указать `LLM_API_KEY`, `LLM_PROVIDER`, `LLM_MODEL`. Этот вариант сохраняет ключ на диске — файл нельзя отправлять другим людям. Старые переменные DeepSeek поддерживаются для совместимости.

## Источники и примеры

В «Источниках» добавьте точный текст нормы, URL, редакцию и область применения. Только отметка специалиста и включённое состояние допускают источник в **следующий** запуск. Система не скачивает содержимое URL и не утверждает, что автоматически проверила актуальность нормы.

Каталог из 12 факторов — рабочая версия по опубликованной методике к постановлению №96. Он требует утверждения командой. Название фактора не считается правовым основанием. При отсутствии норм интерфейс и отчёт явно показывают это ограничение.

Модельные цитаты должны точно присутствовать в документе; цитаты оснований — в проверенном тексте связанного источника. Ответы с выдуманными цитатами или неполным охватом факторов отклоняются.

Подтверждённую находку можно сохранить в примеры. В базе примеров проверьте объяснение, область применения и свяжите проверенные источники. Только после подтверждения пример используется в следующих запусках. Изменение объяснения, применимости или связей требует новой проверки.

## Границы версии

- Локальная демонстрация для одного рабочего пространства. Сервер слушает только `127.0.0.1`, внешнего размещения и совместной авторизации нет.
- DOCX до 3 МБ, основной текст до 80 000 символов. Подготовленный файл нужно сохранить в документ в течение 30 минут, иначе загрузить заново. PDF, OCR, изображения, колонтитулы и сноски не анализируются. Табличная разметка, автоматическая нумерация и сложное форматирование не восстанавливаются. Перед запуском проверьте извлечённый текст в редакторе загрузки.
- Исходный DOCX хранится побайтно с хешем SHA-256. Его можно скачать из истории или полного текста. Для ранее созданных версий без оригинала доступен сохранённый текст; восстановить исходный DOCX по нему нельзя.
- Изменять решения можно только у последнего запуска текущей версии. Архивы доступны для чтения; проверка действует и в API.
- Хранилище — локальный JSON с последовательными атомарными записями. Изменения решения применяются только по кнопке, конфликт старой вкладки отклоняется. После конфликта черновик остаётся в полях: скопируйте нужный текст, затем нажмите «Загрузить сохранённое решение». Для нескольких серверных процессов нужна полноценная БД.
- Результаты модели предварительные. Это демонстрация процесса экспертизы, а не готовое экспертное заключение и не гарантия нахождения всех рисков. Источники проверяет человек.
- Отчёт содержит подтверждённые, отклонённые и нерассмотренные находки, доступные результаты трёх этапов и ограничения. При незавершённом рассмотрении он помечен предварительным.
- Кнопка остановки прерывает ожидание провайдера, но не гарантирует отмену уже учтённого им запроса.

## Сохранение решений

Карточка документа и счётчик ожидающих решений относятся к его последней версии. Проверки предыдущих версий доступны в истории.

Проект редактора подставляется в форму только до первого сохранения решения. Если специалист очистил поле и сохранил решение, пустая редакция сохраняется и не заменяется предложением модели. В Word исходный проект редактора остаётся отдельно для аудита.

Несохранённое решение хранится в памяти открытой вкладки, без записи на диск. При переходе приложение предлагает сохранить работу либо отказаться от черновика; закрытие вкладки и обновление страницы защищает стандартное предупреждение браузера.

## Проверки и устройство

```sh
npm test
npm run dev
```

Проверяются DOCX, валидация цитат, все три этапа с подставным провайдером, исключение непроверенных источников, защита локального API, конфликты решений, история версий и сохранность данных. Тесты работают во временных папках и не требуют ключа.

- `public/` — интерфейс и общий набор визуальных элементов.
- `server/` — локальный HTTP API, этапы анализа, хранилище и DOCX.
- `tests/` — проверки без внешних платных вызовов.
- `shared/` — общие правила версии, архива, контекста цитаты и правки специалиста.
- `public/fonts/` — локальный Inter Tight и лицензия SIL OFL. Внешних запросов для загрузки шрифта нет.
- `docs/` — принятые требования к цепочке проверки и сценарий приёмки.
# Публикация на Vercel

Локальный запуск остаётся прежним. Облачный адаптер `api/index.mjs` использует приватный Vercel Blob, `@vercel/functions/waitUntil` и Node.js 24. `node scripts/build.mjs` копирует общий модуль интерфейса в public. В публикацию не входят `data/`, `.env`, документы сопровождения, тесты и локальные снимки экрана.

Нужны подключённый приватный Blob и `KRUZHIVO_SESSION_SECRET` (криптографически случайный секрет минимум 32 байта в base64url). Секрет должен отличаться для Production и Preview и задаваться как Sensitive в Vercel. Общий DEEPSEEK_API_KEY в облачном адаптере не используется. Исходники и секреты не публикуются как статические файлы.

Каждый браузер получает отдельное рабочее пространство с cookie Secure / HttpOnly / SameSite=Strict, сроком 30 дней. Доступ с другого браузера и совместное редактирование пока не реализованы. Очистка cookie лишает доступа к пространству. Blob-файлы автоматически удаляются по TTL 30 дней после записи; неподтверждённые загрузки — через сутки. Исходные DOCX доступны только через API своего пространства. Локальная рабочая база не переносится в облако.

API-ключ вводится в «Настройки API», передаётся по HTTPS, шифруется AES-256-GCM вместе с настройками назначения и с привязкой к пространству и хранится в приватном Blob. В API возвращаются только статус подключения, без ключа и шифротекста. Отдельного срока действия ключа нет: он действует до ручного отключения в пределах рабочего пространства (его cookie и срок хранения остаются 30 дней). Существующие ключи со старым восьмичасовым сроком также продолжают работать. Отключение очищает сохранённый ключ и запрещает следующие этапы. Уже отправленный провайдеру запрос отменить удалением ключа невозможно. Сами платные запросы не повторяются автоматически. Лимит — один выполняющийся запуск на пространство и 8 запусков API в час.

Изменения состояния защищены атомарной проверкой ETag; проверка ревизии решения специалиста сохраняется. Облачная проверка ограничена 260 секундами; незавершённые запуски старше 5 минут помечаются прерванными при следующем обращении. Документы и ответы провайдера не пишутся в журналы. Учебные сценарии работают без ключа и без запросов к модели.

При развёртывании защита Vercel Authentication сохраняется, если её отключение отдельно не разрешено владельцем. Автоматическое Git-развёртывание не настраивается без проверки подключения репозитория.
