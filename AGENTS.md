# КружИИво — локальная демка

## Решение о хранилище от 20.11.2026

По явному заданию пользователя рабочее облачное хранилище переносится с Neon в существующий приватный репозиторий `mrasos675-oss/kruzhivo`, отдельная ветка `runtime-data`. Рабочие объекты и индекс шифруются AES-256-GCM и сжимаются; ключ остаётся только в защищённой переменной Vercel. Это исключение разрешает сохранение пользовательских документов в зашифрованной ветке данных. Открытые документы, пароли, хеши паролей и секреты в исходную ветку не коммитить. Существующий архив `review-history` сохраняется. Нельзя считать его полной копией недоступной Neon: неперенесённые данные явно отмечать, старую базу до полного экспорта не удалять. Production-адаптер не должен подключаться к Neon даже при наличии прежней DATABASE_URL.

Рабочая среда: Node.js 22.19+ или 24 LTS. Запуск `npm start`, проверки `npm test`. Локальный сервер слушает только loopback. Для Vercel используется отдельный адаптер `api/index.mjs`, приватный Blob и подписанная cookie личного рабочего пространства. Зависимости закреплены в package-lock.json. Модель выбирается произвольным ID, сетевые протоколы и защита адресов находятся в `server/providers.mjs`.

## Неприкосновенные правила

- Не коммитить `.env`, ключи, `data/` и тексты пользовательских документов. Локально ключ из интерфейса хранится только в памяти сервера. На Vercel ключ шифруется AES-256-GCM с привязкой к рабочему пространству, подключение действует до ручного отключения в пределах текущего рабочего пространства; секрет шифрования хранится только в защищённых переменных окружения. По явному решению пользователя 16.11.2026 на Vercel разрешено общее серверное подключение для посетителей по ссылке. Ключ и настройки хранятся зашифрованно в приватном Blob без TTL, управление — по отдельной ссылке владельца с HttpOnly cookie. Посетителям ключ не возвращается; документы и решения остаются раздельными по браузерным пространствам.
- Не подменять реальную проверку подготовленными ответами. Учебный режим всегда явно обозначен.
- Цепочка: Аналитик → Проверяющий → Редактор при необходимости → решение специалиста. Возражения не удалять; исходный текст автоматически не изменять.
- Решения сохранять по кнопке с проверкой ревизии. Новый запуск не перезаписывает прежние результаты и человеческие решения.
- Каталог 12 факторов пока рабочий. Не выдумывать нормативные источники и не объявлять их актуальность автоматически.
- В новые запуски передавать только включённые проверенные источники и допустимые проверенные примеры. Снимки существующих запусков сохранять.
- Не выполнять платные API-вызовы в тестах. Использовать подставной провайдер.

Сопроводительные материалы проекта хранятся отдельно на Google Диске. Не загружать туда код, секреты, служебные файлы и данные проверяемых НПА. Файлы с именем перед расширением, оканчивающимся на «согл», запрещено изменять, заменять, перемещать, переименовывать и удалять. Предложения оформлять отдельно.

Экспертные дела: отдельный снимок документа и анализа; приглашение связывает независимую браузерную сессию эксперта. Госслужащий не подписывает заключение вместо эксперта. Подтверждённые версии заключения неизменяемы, новая правка создаёт новую версию. Не объявлять внутрисистемную кнопку квалифицированной электронной подписью и не утверждать автоматическую проверку аккредитации. Общие нормативные источники редактирует владелец; новые запуски сохраняют свой снимок базы.

На production кабинеты требуют входа по логину и паролю. Тестовые роли official/expert задаются серверной конфигурацией KRUZHIVO_ACCOUNTS со scrypt-хешами. По заданию о регистрации от 16.11.2026 новые аккаунты сохраняются со scrypt-хешами в приватном реестре Blob, роль official/expert фиксируется сервером при регистрации и не меняется через профиль. Регистрация эксперта не подтверждает аккредитацию и не открывает чужие дела или права владельца. Не коммитить действующие пароли и хеши учётных записей. Эксперт не загружает документы и не меняет API; госслужащий не подписывает экспертное заключение. Старую анонимную cookie и capability владельца нельзя использовать вместо аккаунта.
